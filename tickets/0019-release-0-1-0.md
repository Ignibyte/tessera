### 2026-10-21T04:06:52Z

Plan.

- **Two builds** (driver's decision, 2026-10-20, Chad to confirm; recorded in `docs/decisions.md` as Provisional, replacing #1's "what a release ships"): `tessera.*` with the trusted engine and `tessera.csp.*` with the no-eval engine, each as an ES module (`.js`), minified (`.min.js`) and IIFE (`.iife.js`, global `Tessera`), each with its source map, plus `SHA256SUMS` over the twelve files. `docs/consumers.md` says strict-CSP pages load `tessera.csp` and recommends it as the safe default for frameworks.
- **The public API**, `src/start.ts` shared by `src/index.ts` (trusted) and `src/csp.ts` (no-eval), so each build holds one engine: `start(options?)` boots what the test harness boots today (kernel, attributes with the transport's real action seam, patcher, history, transport with the document committer, links with the progress bar, forms, streams, lazy regions, polls) and returns `{ signals, visit, intercept, stop }`. Options: `helpers` only. Errors go to the events that exist (`tessera:error`, `tessera:expired`, `tessera:indeterminate`). A second `start` on a document throws. The IIFE entries start Tessera themselves once the DOM is parsed unless `<meta name="tessera-start" content="manual">`; the ES modules never start on import. Configuration otherwise stays in the protocol's metas.
- **Build and size**: `scripts/build.ts` builds the six files; `npm run size` holds both minified ES modules to their measured size plus 10% and checks that neither build holds the other engine's code (the regexes #22 uses on the engines alone). `scripts/sums.ts` (`npm run sums`) writes `dist/SHA256SUMS`.
- **Tests**: `test/unit/start.test.ts` in jsdom (signals, helpers, a visit through `fetch`, an action reaching `fetch`, the double start, `stop` and a restart). `test/browser/release.spec.ts` replaces `iife.spec.ts`: the reference server's new `?build=` swaps the harness for a release file. Each IIFE starts by itself (a directive applies, a link visit morphs without a reload, an `@post` reaches the server), `tessera-start=manual` waits for `Tessera.start()`, the ES modules start through a small asset; under `?csp=1` the csp build works and the default build's directives fail with `tessera:error`.
- **Docs**: README's public API (loading, configuration, attributes, events, the interceptor seam), `RELEASING.md`, `docs/consumers.md` (pinning, the SHA-256, copying at build time, the server checklist, what AIC and Rustal must change, from `docs/protocol.md` and the design; AIC's checkout is off limits), CHANGELOG `0.1.0`. Known issue in the notes: #30.
- **Release**: version 0.1.0 in `package.json` and `src/version.ts`, merge, tag `v0.1.0` on main, `gh release create` with the twelve files and `SHA256SUMS`, then `gh release download` into a scratch directory and `sha256sum -c`.

### 2026-10-21T04:23:08Z

Blocked: the size budget. Draft PR #31 has everything else (the public API, both builds, sums, tests, docs, version 0.1.0); `npm run check` fails only on size, and test:browser (214) and test:browser:webkit (107) pass.

**What I need.** `dist/tessera.min.js` is 32,285 bytes gzipped against #1's budget of 30,720. Until this ticket the build held only `version` (98 bytes), so no check had ever measured the runtime. "Lower the budget to the measured size plus 10%" would raise it to 35,514, and raising a bar is not mine to do. Terser's options gain nothing; meeting 30,720 means cutting about 1.6 KB gzipped from the source. Details in `docs/decisions.md`, Open.

**Options.**
1. Set the default budget to 35,514 (measured plus 10%) and release now; a later ticket ratchets it down. The csp build gets 44,148 on the same rule either way.
2. A size ticket first (shorter error messages, dedupes across modules), then the release at 30,720.

**Recommendation: 1.** The 30 KB was a starting figure set when nothing was built, and `docs/consumers.md` recommends the csp build to frameworks, which is 40 KB whatever the default build weighs. So 30,720 on the default build does not bound what ships by default.

Also for the driver: #30 (a superseded visit leaves its prefetch running) is a known issue for 0.1.0 unless it should land first.
